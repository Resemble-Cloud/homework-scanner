- 分支：`spike/freebuff-dewarp`
- 基线：`main` @ `670c975`
- 原型：[tools/dewarp_spike.py](../tools/dewarp_spike.py)（Python + OpenCV + NumPy，无新依赖）
- 数据：[docs/quality/dewarp/metrics.csv](quality/dewarp/metrics.csv)
- 对比图：[docs/quality/dewarp/](quality/dewarp/)（3 档曲率 + 3 个失败案例）
- 复现：`python tools/dewarp_spike.py`（十几秒到两分钟，取决于失败案例的边界搜索）
- 本轮**不改** `lib/`、`packages/fairscan_engine/`、`android/`，不接 UI，不引入任何模型。

## 1. 结论

**有条件 Go，但不是「现在移植」。**

- 合成闭环上，几何反解能把弯曲页恢复到接近无损：3 档曲率下方法 B 的 PSNR 提升 +2.21 / +2.06 / +1.34 dB（SSIM 0.8679→0.9167、0.8332→0.8882、0.7709→0.8257），而用真参数的**理论上限**只比它高 0.06–0.09 dB。也就是说**方法本身的天花板基本摸到了，难点全部在「估计」这一侧**。
- 两种方法互补但都不够用：
  - 文本行拟合（方法 A）只修垂直方向，留下水平压缩；位移残差中位数 0.55–0.69 px、P95 3.77–5.58 px（未校正的原始残差是中位 1.18–2.89 px、P95 8.31–21.72 px）。
  - 边缘/圆柱模型（方法 B）在纸面边界清晰时精度高一个量级（中位 0.13–0.21 px、P95 0.62–1.18 px），一旦纸面分割失败会**主动把图改坏**：低对比桌面一例 PSNR 从 15.07 掉到 11.94，SSIM 0.833 → 0.681。
- 因此下一轮该做的是**真实样张验证 + 估计自检（估计不可信就不改图）**，而不是把这两个原型翻成 Kotlin。**本轮不写 Kotlin，也不建议在拿到真实样张前写。**

## 2. 闭环设计

`test_assets/fixtures/page.jpg` 实际是一张「空表格」（黑边框 + 顶部两条长横线），所以脚本只取它中间的空白纸面当纸纹理，再自绘内容：

- 内容：11 行正文，每行 = 一条基线速写 + 一列竖笔画（模拟字母），行距约 71 px。**竖笔画是刻意加的**：只有横线条的页面在 PSNR 上对水平错位几乎不敏感（实测水平校正单独做时 PSNR 只动 0.5 dB），会低估水平压缩的伤害。
- 照片：700×950 的纸页贴在 900×1200 的暗桌面上（桌面 58–84 灰阶 + 噪声）。
- 弯曲（ground truth，已知参数）：

```
theta = (x - cx) / R
x'    = cx + R * sin(theta)                     # 水平压缩，边缘最多
s     = focal / (focal + R * (1 - cos(theta)))  # 越远缩得越小
y'    = cy + (y - cy) * s                       # 文本行向画面中心弓起
```

- 3 档：`level1_mild` R=900、`level2_medium` R=600、`level3_strong` R=380，`focal=1600`，`cx/cy` = 画幅中心。page 宽 700、弯曲圆柱半径 380 时，纸面左右边缘的水平压缩量约 8 / 22 / 44 px，这是「中度到偏强」的弯曲，不是极端卷曲。
- 正向 warp 生成弯曲照片，两个方法各自尝试还原，与平面 ground truth 逐像素比较。

## 3. 两种方法

**方法 A：文本行拟合（只修垂直）**

自适应阈值 → 水平形态学连接（核宽 = 图宽/18）→ 连通域筛「够宽够扁」的行带 → 逐列取该行带最下方墨迹行作为基线 → 以**纸面水平中心列**（弯曲模型在该处是恒等）为各行目标行 → 对每一列用全部行节点做最小二乘拟合 `shift(x, y) = a(x) + b(x) * y`（比在相邻行之间做分段线性更稳，也不会把行距改形）→ 平滑 `a(x)`、`b(x)` → 逐列 remap。**不做水平校正。**

**方法 B：页面边缘 / 圆柱模型（垂直 + 水平）**

Otsu + 最大连通域分割纸面 → 逐列取纸面上下边界曲线 → 网格搜索 `(R, focal, cy)`（45×7×25 组），用上下两条边界曲线的最小二乘残差定标 → 用拟合到的圆柱解析反解整幅位移场 → remap。只用纸面轮廓，不看内容。

## 4. 指标

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| 文本行直线度 | 每一行带基线曲线（宽平滑后）在 x 方向的 std，px | 越小越直 |
| PSNR / SSIM | 与平面 ground truth 在纸页内部（内缩 6%）比较 | 越大越好 |
| 位移误差 中位 / P95 | 输出像素取到的源点 vs ground truth 源点，在弯曲照片坐标下的距离，px | 越小越好 |
| 耗时 | 单次调用，900×1200 | 记录 |
| 行带数 | 该图上检出的行带数量（检测是否崩掉） | 参考 |

**指标本身的局限（重要）**：在这套合成内容上，PSNR/SSIM 主要由垂直分量决定。实测「只用真参数修水平」的 PSNR 在 level3 反而从 13.19 掉到 10.19——因为弯曲的垂直位移（最坏约 38 px，接近半个行距）会和水平位移在逐像素比较里产生偶然抵消，校正一个轴反而破坏这种抵消。所以**PSNR/SSIM 只能作为辅助，排序主要看位移误差**。

- **方法 B 拿到理论上限增益的 96%**（level1 2.21/2.29 dB、level2 2.06/2.15 dB、level3 1.34/1.40 dB），而它的 R 估计误差很大（1534 vs 真值 900）——见下。
- **方法 A 只拿到理论上限增益的 24% / 42% / 64%**（分别提升 0.54 / 0.91 / 0.90 dB），差距来自两点：只修垂直；以及基线估计本身有 ~0.5–0.7 px 的中位误差，而 PSNR 对文字页上的亚像素错位非常敏感（位移误差只掉到 0.55–0.69 px 中位，剩下的是水平分量）。
- 直线度：弯曲页 2.28–3.77 px，两种方法都压到 1.0–1.4 px，**≈ ground truth 自己的 1.38 px 底噪**（该底噪来自合成笔画的末端抖动，不是弯曲）。方法 A 的 0.84 px 略低于底噪，是因为它按定义把基线拉成常数、连笔迹本身的抖动也一起抹平了。

## 6. 关键发现

1. **`R` 与 `focal` 从纸面轮廓上不可分辨。** 方法 B 拟合出的 R 分别是 1534 / 483 / 483（真值 900 / 600 / 380），但边界残差只有 0.90–1.46 px：因为只有组合 `R*(1-cos θ)/focal` 决定垂直收缩，多组 (R, focal) 给出同一条边界曲线。后果是**垂直方向恢复得很好（s(x) 误差 < 0.5%），水平映射却不可信**——mild 档的水平校正实际上几乎等于没做。这条在真实样张上同样成立，需要额外信息（文本行的水平压缩、纸张纹理）才能定标水平方向。
2. **弯曲越轻越难估。** mild 档的 PSNR 增益全靠垂直分量，水平方向被完全漏掉；strong 档反而 R 估得准（483 vs 380）。
3. **行带检测本身会被弯曲打崩。** 强弯曲时同一行的 bbox 高度超过「够扁」门限（`bh ≤ 6%` 图高），行带被丢弃：`failure_border_invisible` 里 11 行只剩 1 行通过，方法 A 因此主动放弃（「可用基线不足 → 原样返回」）。这是文本行方案在真实强弯曲页上的一个隐性上限。
4. **两种方法互补**：纸边不可见时 B 失效而 A 仍能工作（前提是行带检测没崩）；没有文本行时（图表页）A 无事可做而 B 仍能工作（PSNR 18.47 → 20.23）。
5. **错误的估计会让结果更差，必须自带自检**：`failure_low_contrast_desk` 里边界残差 234 px（明显不可信），方法 B 仍然照做，PSNR 从 15.07 掉到 11.94、SSIM 0.833 → 0.681、位移误差中位 24 px。**任何将来接入的展平都必须以「估计自检通过才改图」为前提。**

## 7. 失败案例（全部来自合成样本，不是真实照片）

| 案例 | 构造 | 结果 | 说明 |
| --- | --- | --- | --- |
| `failure_border_invisible` | 纸页铺满画幅（1500×1900 的页面铺在 900×1200 画幅上），看不到纸边 | A：11 行只检出 1 行 → 原样返回；B：R 收敛到搜索上界 6000（≈没弯）→ 几乎不动 | B 失去边界线索即失效；A 因行带 bbox 过高被门限丢弃 |
| `failure_low_contrast_desk` | 桌面亮度 196–224，接近纸面 250 | A：墨迹检测失败，0 行带 → 原样返回（位移误差 1.78 px = 原始位移）；B：边界残差 234 px，位移误差中位 24.37 px，PSNR 15.07 → 11.94 | 分割失败 → 模型错 → **图被改坏**（比什么都不做差 6 倍） |
| `failure_no_textlines` | 圆、三角、斜线填充、几段短标注，没有长文本行 | A：0 行带 → 原样返回；B：仍能展平，PSNR 18.47 → 20.23 | 图表/插图页：文本行方案无效 |

真实场景里还会碰到这里没覆盖的：手/手指压页、纸面反光、双页摊开、非圆柱形弯曲（斜向弯曲、S 形）、有透视的斜拍（本 spike 的模型里没有相机透视）。**结论只能覆盖「单页、文字为主、纸边清晰、近似圆柱」的情形。**

## 8. 代价

- 方法 A：46–107 ms（900×1200，Python）；只需要灰度 + 阈值 + 连通域 + remap。
- 方法 B：161–597 ms，其中绝大部分是边界参数网格搜索（7875 组 × 逐列残差）；换成解析最小二乘或粗到细搜索可以降一个量级，但仍是「每次扫描多几十毫秒到几百毫秒」的量级，在 4MP 预算的页面上还会放大。
- 两者都需要一次额外的 resize/remap，会带来一次重采样模糊（本 spike 没评估它对小字/上下标的影响）。

## 9. 建议的下一步

1. **不移植 Kotlin。** 先拿 3–5 张真实「轻度/中度弯曲、文字为主、纸边清晰」的照片复核本 spike 的两个方法；没有真实样张之前，任何移植都是在没验证的模型上写生产代码。
2. 若真实样张验证通过，下一轮做**联合估计**：用文本行基线的垂直信息 + 纸面边界的几何约束一起拟合位移场，并对水平压缩用内容信息（字符宽度/纹理）单独定标——单靠轮廓无法定标水平方向（第 6 节第 1 条）。
3. 必须同时做**估计自检**：边界残差、行带数、拟合参数越界都要触发「放弃修改」，宁可退回原图。
4. 真实样张只能放 `test_assets/real_samples/`（本地、已 gitignore），不提交。

## 10. 限制与不做

- 只在合成样本上验证，**不能替代真实样张验收**；合成内容是我自己画的笔画，不是真实作业。
- 没有相机透视、没有纸张纹理建模、没有手指/反光、没有双页与非圆柱弯曲。
- 指标里 PSNR/SSIM 对水平错位不敏感（第 4 节），排序主要依赖位移误差；`displacement_error` 依赖已知的 ground truth 模型，真实照片上没有这个指标。
- 没有评估重采样对小字/上下标的损失，也没有评估与现有 FairScan 增强链路的先后顺序。
- 不改 `lib/`、`packages/fairscan_engine/`、`android/`，不接 UI，不引入深度学习模型，不新增依赖，不改 App 默认输出。
